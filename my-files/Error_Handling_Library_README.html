Error Handling Library

A Java library exploring consistent error handling for Spring MVC and Spring WebFlux applications.

Overview

The project explores how to provide consistent HTTP error responses across servlet and reactive Spring applications. It is organized as a multi-module Maven project, separating shared functionality from web-stack integrations and supporting components.

The tests covers request validation, Spring Security failures, exception handling, and creation of Spring ProblemDetail responses.

Purpose

Applications need to explain errors to users and operators in a consistent way. This project explores a reusable approach for Spring MVC and reactive applications, so developers can handle common failures more consistently instead of building the same patterns separately for each application.

Architecture and modules

The servlet and reactive implementations have separate integration modules. Shared Spring and core modules provide reusable pieces; starter modules collect dependencies for each web stack.

Module Responsibility
error-handling-shared Shared types used by other modules.
error-handling-core Core library functionality.
error-handling-spring-core Shared Spring integration, including ProblemDetail and trace-ID provider abstractions.
error-handling-servlet Servlet / Spring MVC error-handling integration.
error-handling-reactive Reactive / Spring WebFlux error-handling integration.
error-handling-logback Logback-related integration.
error-handling-micrometer-tracing Micrometer tracing integration; currently not included in the root Maven aggregator.
error-handling-servlet-starter Dependency bundle for servlet applications.
error-handling-reactive-starter Dependency bundle for reactive applications.

Tested behavior

The module tests provide examples of the project’s current behavior:

  • Shared Spring functionality: tests cover the default and custom ProblemDetailFactory and TraceIdProvider. The default factory tests check status, timestamp, correlation ID, and optional trace ID properties.
  • Servlet integration: tests exercise default handler and locale-resolver bean registration, a successful request, request validation errors, unauthenticated and forbidden requests, and an unexpected-exception response.
  • Reactive integration: tests exercise default handler and locale-resolver bean registration, a successful request, missing parameters, validation errors, unauthenticated and forbidden requests, and an unexpected-exception response.
  • Logging integration: tests exercise a servlet test application and authenticated and unauthenticated request paths.
  • Tracing integration: a test class covers trace-provider selection scenarios. The module is not included in the root aggregator, and the current test setup should be reviewed before treating this integration as verified.

These tests are not a guarantee that every error category or configuration is supported. For example, some test cases inspect that a response body exists without asserting its complete contents. Needs to be developed/implemented.

Technology stack

  • Java 17
  • Maven and the Maven Wrapper
  • Spring Boot dependency management 3.5.5
  • Spring MVC and Spring WebFlux
  • Spring Security and Jakarta Validation APIs
  • SLF4J and Logback
  • Micrometer Tracing module

The project uses Spring Boot dependency management; this does not by itself establish compatibility with every Spring Boot release.

Prerequisites

  • JDK 17
  • The Maven Wrapper

Build and tests

From the repository root, run the Maven wrapper to build the reactor and execute the tests Maven discovers:

mvn clean verify

Configuration notes

The properties needs to be enabled to use a specific feature, as follows:

error.handling.servlet.enabled=true
error.handling.reactive.enabled=true
